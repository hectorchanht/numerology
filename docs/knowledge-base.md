# 知識庫設計

## 兩層結構

```
packages/knowledge/
  data/            结构化规则(JSON,引擎直接命中)—— 主力
  src/             类型定义 + 查询函数
  corpus/ (后续)   清洗后的古籍原文(RAG,仅用于"引经据典")—— 锦上添花
```

**判斷邏輯只依賴 `data/` 的結構化規則,不依賴 RAG 檢索。** 文言文原文檢索容易"檢索到卻用錯場合",故只作出處增強,不參與判斷。

## 古籍 → 結構化的映射

| 書 | 性質 | 最優用法 |
|---|---|---|
| **窮通寶鑑**(欄江網) | 查找表:日主 × 月令 → 調候用神 | 直接轉 JSON 表(`qiongtong.json`)。ROI 最高,幾乎零幻覺 |
| **滴天髓** | 原理 / 心法(賦 + 注) | 蒸餾成判斷啓發式(通關 / 調候 / 病藥觸發條件) |
| **三命通會** | 百科式(格局 / 神煞 / 十神) | 挖取格局定義與十神性情;不整本入庫 |
| **紫微斗數全書 / 太微賦** | 星曜 / 四化 / 格局 | 安星規則交給 iztro;格局與四化解讀蒸餾成規則 |

> ⚠️ 古籍**原文**屬公有領域(ctext.org / 維基文庫);現代**點校本 / 白話譯註本有版權**,不得使用。

## 降低幻覺的槓桿排序

1. **確定性排盤引擎** —— 消除最大來源(算錯節氣 / 閏月 / 安星 / 起運)。
2. **結構化規則命中** —— 給解讀提供準確的命理詞彙與判斷依據。
3. **古籍 RAG(可選)** —— 僅增強可信感與邊緣案例,不決定判斷邏輯。

## 數據文件約定

每個結構化數據文件帶元信息:`source`(出處)、`version`、`reviewed`(是否經人工校對)。
未經人工校對的 AI 抽取數據,`reviewed: false`,在解讀層需降權或標註。

## 層級(tier)與出處(cite)約定

- `meta.tier`:整份資料的可信層級,四選一:
  - `classical` 原典(古籍、古代文獻)
  - `scholarly` 學者詮釋(如 Fideler;Agrippa 屬文藝復興原典,但其行星對應屬詮釋,逐條標)
  - `modern` 近現代發明或有爭議(如畢氏生命靈數的現代算法、Dreamspell)
  - `science` 同行評審研究
- 單條可覆寫 `tier`,並帶 `cite: { work, author, year, locator }`,locator 為頁碼、章節或 URL。
- `tier` 為選填;缺省時 UI 顯示「未分級」,不得猜一個層級填入。
- 現代著作(如 Fideler 1993)只取事實與摘要加頁碼,不搬原文;古籍原文屬公有領域可引。
- 各體系一覽與狀態見 `docs/domains.md`。

## 並行工作協調

`packages/knowledge/` 由另一工作流持續加入資料(如 `greek-gematria.json`、`planetary-squares.json`、`agrippa-*.json`)。
多體系功能只**讀取**這些檔案,不改其內容;資料衝突時以並行工作的版本為準。
`pythagorean-numbers.json`、`science-notes.json` 若與並行工作重名,改為讀取對方版本。
內聯模組(`src/*.data.ts`)由 JSON 生成,JSON 更新後須重新生成,並由測試比對整份匯出與 JSON 一致。
